# Qwen4-Max：全天候 AI 新同事

> [!info] 报告信息
> [技术博客](https://qwen.ai/blog?id=qwen4-max) · 作者：Qwen Team · 页面日期 2026-11-16
> 这是发布博客，不是论文：没有 arXiv、没有公式、没有消融。架构和预训练只有一节概述；其余大部分是应用案例。
> 模型**不开源**（通过千问 AI 平台 API / Token Plan 使用）；博客说 Qwen4 系列的小尺寸模型"将陆续开源"。

## 一句话总结

Qwen4-Max 是 Qwen4 系列的第一款模型：2.4T 总参数、每 token 激活 71B 的稀疏 MoE，原生视觉、百万 token 上下文。架构上把注意力换成"3 层 Gated DeltaNet + 1 层稀疏注意力"、残差流扩成 4 条带门控的分支、并加了 328B 参数的 N-gram Embedding。定位是能长时间自主推进任务、分阶段交付成果的"智能体同事"。

## 要解决什么问题

- **长程任务**：智能体要连续干几小时甚至几十小时（博客里最长的案例是 48 小时自主化学实验），需要长上下文便宜、推理 token 少。
- **交付而非问答**：目标是交出可用的成品（Excel 底稿 + PPT、86 页尽调报告、可玩的游戏、可加工的刀路），而不是回答。
- **长程智能体"蒙头做事"**：用户看不到中间进度、无法纠偏 → 提出 Live Delivery（边做边交付）。
- **成本**：相比 Qwen3.8-Max，激活参数少约 25%，推理 token 少 24–49%，API 降价。

## 方法

### 架构（博客 Figure：模型结构）

| 项目 | Qwen4-Max | Qwen3.8-Max（对照） |
|---|---|---|
| 总参数（主干） | 2.4T | 2.4T |
| 每 token 激活 | 71B | 95B |
| 额外 N-gram Embedding | 328B | — |
| 上下文 | 1M tokens | — |

三处改动，分别对应 Attention、Residual、Embedding：

1. **GDN + Qwen Sparse Attention（QSA）混合注意力**
   - 每 4 层一组：3 层 **Gated DeltaNet**（线性注意力，把历史压成固定大小的状态）+ 1 层 **QSA**。
   - QSA 用一个轻量 Indexer，**按 block 粒度**挑选相关上下文再做注意力，降低长序列的注意力计算和索引开销。
   - 每层的 FFN 都是 MoE。
2. **Gated Residual（GR）**
   - 残差流扩成 **4 条并行分支**（图中"Expanded Residual"的四个圆圈）。
   - 每个子层前有 **GR Read**（从 4 条分支读出一个 hidden state 送进注意力或 MoE），子层后有 **GR Write**（把输出写回 4 条分支），读写都带动态门控。
   - 最后一层也经过 GR Read 再进预测头；另有 MTP（多 token 预测）模块。
   - 作用：增强跨层信息传递、提升训练稳定性。思路和 Hyper-Connections 一类"多路残差"相近（博客没提）。
3. **N-gram Embedding**
   - 按局部上下文（n-gram）**查表**，只在**第 2 层**注入，补充局部 token 模式的表示。
   - 查表几乎不费算力，用 328B 参数换模型容量。思路类似 Engram / 记忆查表层（博客没提）。

### 预训练

- 2.4T 规模下全程 loss 平稳下降，**没有 loss spike**，博客归功于架构和训练优化（未说明具体是什么优化）。
- 没有给出训练数据量、token 数、算力。

### 后训练（博客几乎没写）

- 只提到几点：软件工程训练任务里在功能检查外加了**代码安全检测**；网络安全数据按用途筛选，保留防御类、剔除进攻类；CBRN 有专门的安全后训练数据。
- 推理强度分 Low / High / Xhigh 三档。

### 产品侧

- **Live Delivery（持续交付）**：先交付可用首版，再迭代交付新版本；用户看每一版来纠偏，智能体据反馈调整计划。同时开源 **Qwen-Live-Delivery-Plugin**。
- **"模型-框架-产品"协同设计**：与 Qoder 等产品团队一起设计模型、智能体运行框架和产品，以端到端任务交付质量做验收。

## 局限 / 存疑

- **没有技术报告**：架构只有一张示意图和三段文字，GDN/QSA 的层数、专家数、Indexer 设计、GR 门控形式、N-gram 表的构造都没有。训练数据、算力、后训练方法基本空白。
- **BPB 对比不完全公平**：GLM 和 Kimi 是后训练模型；且 BPB 依赖分词和评测语料，内部评测集不公开。
- **基准选择**：不少是新的或第三方排行榜引用（Mercor、Artificial Analysis、LM Arena、Vals），JobBench 用的是"更新后的数据集和评测代码"自测。Work360 是自建基准，只对比了自家上一代。
- **编程和视觉仍落后**：Terminal-Bench 4.0 比 Kimi K3.1 低约 19 分，ProgramBench 落后 Opus 5.5 约 34 分；视觉三项都排在闭源模型之后，"原生视觉"的优势没有体现在数字上。
- **应用案例都是单例展示**，大多是合作方场景，没有成功率或重复次数；材料和药物案例的"发现"要等湿实验/后续验证。
- **Token 效率只和上一代比**，没和其他模型比每任务 token 或成本。
- 柱状图数字是我从图上读的，表格需对照原图核对。

## 与其他论文的关系

- **Gated DeltaNet**（Yang et al., 2024）：线性注意力的一种，Qwen3-Next 已采用 GDN + 全注意力 3:1 混合；Qwen4 把全注意力层换成了块级稀疏的 QSA。
- **块级稀疏注意力**：思路接近 DeepSeek 的 NSA / DSA（带 Indexer 的稀疏注意力）、Kimi 的 MoBA。
- **多路残差**：与 Hyper-Connections / mHC 一类扩展残差流的工作同路数。
- **N-gram / 查表式嵌入**：与 DeepSeek Engram、Over-Tokenized Transformer 等"用查表扩参数不扩算力"的思路相近。
- **与本库的关系**：长程智能体自主推进 + 用可量化反馈改进自身所用系统（云调度案例），与 `topics/递归自我改进RSI.md` 的主题相关；"在 Blender / 游戏引擎里边运行边调整"的能力，与 MirroS AgentGarten（`mirros/notes/01_AgentGarten.md`）的代码世界 + 智能体思路可以对照。
