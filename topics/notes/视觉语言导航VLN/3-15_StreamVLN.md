## 一句话总结

把 LLaVA-Video 7B 改成**流式多轮对话**的导航模型：每来一帧观测就是一轮"观测 → 动作"对话，跨轮**复用 KV 缓存**，所以每步只需要对新帧做 prefill。为了让上下文不随步数无限增长，用"快慢"两层：**快**的是最近 8 轮对话的滑窗 KV 缓存，负责及时出动作；**慢**的是窗口滑走后把其中的视觉 token 收进一个定长记忆（8 帧 × 196 token），还可以用深度把 patch 反投影到体素、同一体素只留最新那个 token 来**免训练剪枝**。纯 RGB 下 R2R-CE val-unseen SR 56.4%、RxR-CE SR 54.4%（加了额外数据的版本），真机 Go2 在难度最高的跨房间办公室场景 SR 60%，NaVILA 和 NaVid 都是 0。

## 要解决什么问题

Video-LLM 做 VLN（NaVid、Uni-NaVid、NaVILA 这一类）要在三件事之间取舍：**细粒度视觉理解、长程上下文、计算效率**。作者把现有做法分成两种：

- **固定帧数采样**（NaVILA、MapNav）：时间分辨率不够，需要细粒度时间变化时低层动作预测不准。
- **把视觉 token 压成稀疏记忆 token**（NaVid、Uni-NaVid，用池化或 token 合并）：控制了 token 数，但丢了时间和视觉细节。

而且两种都**每一步都刷新整个对话上下文**，训练和推理里都有大量重复计算，既拖慢真机部署也限制了数据规模。作者想要的是：上下文和推理代价都有上界，同时还能处理长视频流。

另一个观察（[[topics/papers/视觉语言导航VLN/3-15_2507.05240_StreamVLN.pdf#page=1|图 1]]）：第一视角导航视频即便做了时间采样，在 Video-LLM 的高分辨率输入下 **patch 级的空间冗余**仍然很大，而 3D 几何正好可以拿来去掉这种冗余。

## 方法

总览见 [[topics/papers/视觉语言导航VLN/3-15_2507.05240_StreamVLN.pdf#page=2|图 2（第 2 页）]]。骨干是 **LLaVA-Video 7B**（语言模型 Qwen2-7B），输入是语言指令 + RGB 图像流。

### 把导航当成多轮对话（§III-A）

- 每一轮 `d_i = (o_i, a_i)`：收到新观测 `o_i`，自回归地生成动作 `a_i`。第 i 步的完整输入是 `o1 a1 o2 a2 … o(i-1) a(i-1)`。
- 关键在于**跨轮复用 KV 缓存**：如果不复用，每轮都要对全部历史重新 prefill；复用后只有新观测的 token 需要 prefill。作者说跨轮复用能省掉 99% 以上的 prefill 时间。
- 动作的具体形式正文没写（每轮输出几个动作 token、动作空间是不是 VLN-CE 的离散"前进 / 左转 / 右转 / 停"），只在实验里出现"4 个动作"和"8 个动作 token"两种说法，见"局限 / 存疑"。需核对代码。

### 快：滑窗对话上下文（§III-B）

- 问题：KV 缓存随轮数线性增长（作者举例 2K token 约占 5 GB 显存），而且 Video-LLM 在过长上下文上推理变差。
- 做法：只在活动窗口里保留最近 **N 轮**对话的 KV（实验里 N = 8）。窗口满了以后：
  - 窗口里**非观测**的 token（提示词、生成的动作）的 KV 直接丢掉；
  - **观测** token 的状态被加工成记忆 token 状态 `M_j`，供后面的窗口使用（下一节）。
- 新观测的动作由三样东西决定：当前观测、所有记忆 `{M_0 … M_j}`、当前窗口里已有的 KV 缓存。

### 慢：记忆上下文 + 体素剪枝（§III-C、算法 1）

- **先做时间采样**：照 NaVILA 的做法，采固定帧数。作者试过训练时直接做特征级压缩（平均池化、可学习的 Q-Former），效果掉很多，原因是改变了预训练的输入分布、破坏了预训练知识。所以空间上不压特征，只**挑 token**。
- **体素剪枝（免训练）**：
  1. 用深度把视频流里的 2D patch 反投影到一个共享的 3D 空间，划分成均匀体素；
  2. 每 K 帧为一段，同一段里多个 token 落到同一个体素时，**只保留最新那一帧的 token**；
  3. 如果某一帧剩下的 token 少于 θ·H·W，把这一帧整个去掉。
- 和面向一般离线视频的 token 压缩（如 PruneVid）比，这个方法靠几何而不靠特征相似度或大注意力矩阵，所以更省算力，也能直接作用在流式视频和 KV 缓存上。
- 注意：这一步要用**深度和位姿（里程计）**，见"局限 / 存疑"。

### 训练数据与配方（§III-D、[[topics/papers/视觉语言导航VLN/3-15_2507.05240_StreamVLN.pdf#page=3|图 3]]）

| 类别 | 来源 | 规模 | 占比 |
|---|---|---|---|
| 导航（VLA，共 67%） | Habitat 里采 60 个 MP3D 场景：R2R、R2R-EnvDrop、RxR | 45 万段视频片段 | 31% |
| | ScaleVLN 的子集，700 个 HM3D 场景 | 30 万 | 20% |
| | DAgger：第一阶段模型跑 rollout，最短路径跟随器当专家给纠正 | 24 万 | 16% |
| 通用多模态（共 33%） | 视频 VQA：LLaVA-Video-178K + ScanQA | 24.8 万 | 17% |
| | 图文交错：MMC4 | 23 万 | 16% |

- 两阶段训练（§IV-B）：
  1. 只用专家（oracle）VLN 轨迹微调 1 个 epoch；
  2. 用第一阶段模型采 DAgger 数据，再用 VLN + 通用多模态数据混合训练 1 个 epoch。
- 学习率峰值：语言模型 2e-5，视觉编码器 5e-6；每步 128 段视频片段；共约 1,500 A100 GPU 小时。
- 训练用 16 帧左右的短片段（引言里的例子），推理时靠快慢上下文接到长视频流上。

- **Prune-Mem**：只对 8 帧记忆剪枝，记忆 token 减少 28%（R2R）/ 22%（RxR），R2R 反而略升（56.4 → 57.4）。作者解释为记忆里本来就有冗余，剪掉后模型更专注。

- 作者另说 HAMT 用完整 ScaleVLN（300 万条轨迹）训练，StreamVLN 只用了"15 万的子集"就超过它，数据效率更高。

### 3D 问答：ScanQA（表 II，第 6 页）

每个场景用 16 张多视角图回答。StreamVLN：Bleu-4 15.7、Rouge 48.3、EM 28.8，比 NaviLLM（12.0 / 38.4 / 23.0）和 NaVILA（15.2 / 48.3 / 27.4）略好。[[topics/papers/视觉语言导航VLN/3-15_2507.05240_StreamVLN.pdf#page=4|图 4]] 举了一个例子：VQA 能力让它能理解训练里没见过的指令（"走到蒙娜丽莎照片前马上停下"，交换两张照片的位置后仍然走对）。

### 真机（[[topics/papers/视觉语言导航VLN/3-15_2507.05240_StreamVLN.pdf#page=5|图 5]]、图 6）

- **平台**：宇树 Go2，装一台朝上倾斜的 RealSense D455（RGB-D）。模型跑在**远程 RTX 4090 工作站**上，机器狗把图像流传过去，服务器回传动作。

**记忆大小与窗口（表 IV，第一阶段只用专家数据训练）**：

| 记忆 | 窗口 | SR | SPL |
|---|---|---|---|
| 2×196 | 8 | 37.3 | 34.2 |
| 4×196 | 8 | 38.9 | 35.4 |
| **8×196** | **8** | **45.5** | **41.6** |

| 8×196 | 4 | 41.4 | 37.5 |
| 8×196 | 2 | 43.7 | 40.3 |

- 记忆从 2 帧加到 8 帧涨 8.2 个点；但**把全部历史都当记忆反而更差**，作者解释为过长、长度多变的上下文在训练时引入偏差，测试时泛化变差。
- 窗口越小，滑动越频繁，训练样本越多（窗口 8 / 4 / 2 分别约 45 万 / 81.5 万 / 150 万），训练成本线性上升、类别也更不平衡；窗口 8 效果最好而且训练最省。

**KV 缓存复用的延迟（[[topics/papers/视觉语言导航VLN/3-15_2507.05240_StreamVLN.pdf#page=7|图 7]]）**：

- 全部轮次都复用：一直约 0.27 s，但缓存全存着，显存开销大。
- 滑窗复用（StreamVLN 的做法）：平时约 0.27 s，每个新窗口开头要 prefill 上一窗口的上下文，第 9、17 轮出现约 0.48 s 的尖峰。
- 不跨轮复用（以前的做法）：每个窗口内延迟随轮数一路涨到约 0.48 s。

## 局限 / 存疑

- **正文数字和表格对不上（需核对）**：
  - §IV-C 写 R2R "SR 56.9%、SPL 51.9%"，RxR "SR 52.9%、SPL 46.0%"；表 I 里 StreamVLN† 是 R2R 56.4 / 50.2，RxR 54.4 / 45.4。看起来像 v1 的数字没跟着 v2 的表更新。
  - 数据消融正文写的增量（联合训练 +5.3 / +4.1、ScaleVLN +2.9 / +3.7、DAgger +5.5 / +3.8、RxR +7.8 / +7.3）和表 III 算出来的（+5.2 / +3.4、+3.6 / +3.0、+6.2 / +3.1、+8.5 / +6.6）都不一致，只有 MMC4 的 +2.0 / +1.5 对得上。
  - ScaleVLN 用了多少：§III-D 说 30 万个样本，§IV-C 说"15 万的子集"。可能一个是样本数、一个是轨迹数，论文没说清。
- **"纯 RGB"的范围**：基础版 StreamVLN 确实只用单目 RGB；但体素剪枝要深度 + 位姿，所以表 I 里**最好的 R2R 数字（Prune-Mem 57.4）不是纯 RGB**。真机用的是 RGB-D 相机，真机上开没开剪枝、位姿从哪来没有说。
- **"长程记忆"其实是 8 帧**：慢记忆是固定 8 × 196 个 token（照 NaVILA 的定数时间采样），而且消融显示全部历史当记忆反而变差。所以它解决的是"上下文有上界、推理不随步数变慢"，而不是"记住更久"。体素剪枝在 8 帧里能省 22–32% 的 token，但论文**没报告剪枝带来的延迟或显存收益**，只报了 token 数。
- **动作粒度说法不一**：真机部分是"0.27 s 出 4 个动作"，图 7 的说明是"生成 8 个动作 token"；每轮到底输出几个动作、动作空间是什么，正文都没交代。
- **真机评测比较薄**：每个场景 20 次，但没说是几条路线、指令谁写的；基线有没有在同样的数据上微调也没说。延迟里通信占大头（室外 1.0 s，是推理的近 4 倍），且依赖远程 4090，没有机载部署。
- **ScanQA 表头可能错位**：表 II 的列顺序写的是 Bleu-4 / Rouge / Meteor / Cider / EM，但"Meteor"一列是 100 左右，按惯例更像 CIDEr。只影响阅读，不影响结论。
- **引用小错**：语言模型说是 Qwen2-7B，引用的却是 Qwen2.5 技术报告。
- **仿真与真机的差距**：训练全部来自 Habitat（MP3D + HM3D），没有真实数据。后来的 [[topics/notes/视觉语言导航VLN/3-40_Compass-1|Compass 1]] 正是拿这一类"仿真训练的单目视频大模型"作为真机上会失效的代表来批评。

## 与其他论文的关系

- **直接前身（单目 Video-LLM 导航）**：[NaVid](https://arxiv.org/abs/2402.15852)（3-03）、[Uni-NaVid](https://arxiv.org/abs/2412.06224)（3-06）把视觉 token 压成稀疏记忆；[NaVILA](https://arxiv.org/abs/2412.04453)（3-05）、[MapNav](https://arxiv.org/abs/2502.13451)（3-07）采固定帧数。StreamVLN 的时间采样直接照 NaVILA，主要变化是**跨轮复用 KV 缓存**，不再每步重建上下文。
- **同组后续**：[DualVLN](https://arxiv.org/abs/2512.08186)（3-24，开源为 InternVLA-N1，同在 InternRobotics）走"慢 VLM 出像素航点 + 快扩散策略出轨迹"的双系统，"快慢"从上下文层面换到了系统层面。
- **在效率上直接对比 StreamVLN 的后续**：[Efficient-VLN](https://arxiv.org/abs/2512.10310)（3-25）同样复用 KV 缓存只处理新帧，加连续 RoPE、动作隔离掩码打包训练和自适应 DAgger，专题表里记的是 R2R-CE SR 73.2%，延迟比 StreamVLN 低 28%。
- **另一种"定长记忆"**：[JanusVLN](https://arxiv.org/abs/2509.22548)（3-21）把语义编码器和 3D 几何编码器的历史 KV 当定长隐式记忆，同样只用 RGB；可以和 StreamVLN 的"8 帧 token + 体素剪枝"对照看。
- **把它当基础或基线的工作**：
  - [[topics/notes/视觉语言导航VLN/3-40_Compass-1|Compass 1]]（3-40）：把这一谱系的"全部历史帧 / 启发式压缩"作为批评对象，改用稀疏关键帧 + 历史轨迹图 + VQA 监督。

## 摘要（中文）

真实环境里的视觉语言导航要求智能体处理连续的视觉流，并以低延迟、依据语言指令生成动作。基于视频的大语言模型（Video-LLM）推动了近期的进展，但现有基于 Video-LLM 的 VLN 方法常常要在细粒度视觉理解、长程上下文建模和计算效率之间取舍。我们提出 StreamVLN，一个流式 VLN 框架，采用快慢混合的上下文建模策略，支持在交错的视觉、语言和动作输入上做多模态推理。快速流式的对话上下文通过多轮对话的滑动窗口实现及时的动作生成；慢速更新的记忆上下文用 3D 感知的 token 剪枝策略压缩历史视觉状态。借助这种快慢设计，StreamVLN 通过复用 KV 缓存实现实时对话，在上下文规模和推理代价都有上界的前提下支持长视频流。在 VLN-CE 基准上的实验显示，它以低延迟达到了最先进的性能，保证了真实部署中的鲁棒性和效率。
