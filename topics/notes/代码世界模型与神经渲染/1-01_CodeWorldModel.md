## 一句话总结

一篇"立范式"的论文：把世界模型拆成**编码智能体（世界大脑）+ 代码（高频执行）+ 视频模型（视觉实现）**三件事。智能体只做低频的复杂决策（解释事件、推后果、改机制），把决策写成可复用的代码；代码每步更新位置、碰撞、数值规则等**显式持久状态**；状态通过一个叫 **proxy（代理）** 的粗糙中间表示，经确定性的轻量编译器光栅化成**代理视频**（对数深度 + 语义 ID 图，1/4 边长），和结构化文字一起条件 MiniMax-H3 Ref2VA 生成画面。原型只用 **157 段、约 5.6 小时**的配对游戏录像（图注说是 GTA V）对 H3 的全部 50 个 block 做 rank-128 LoRA（约 5.96 亿可训练参数，8 张 H800、3534 步），推理时由 GPT-5.6 Sol 拿现成游戏代码当模板搭简单世界、录代理视频，再由 H3 用 20 步 Euler 生成 124 帧 1344×768 的片段。**全文没有任何定量指标，也没有实现自回归实时生成**——专题里常引用的"5.1 s/块"来自另一个仓库 Streaming CWM，不是这篇论文。

## 要解决什么问题

- **视频世界模型只能看到结果、看不到机制**：游戏画面是固定代码跑出来的，但代码在渲染后就被丢掉了，模型只能从稀疏的视觉后果里反推规则；很多状态变化发生在画面外或超出上下文窗口（现有视频模型训练窗口通常不到一分钟，而世界里的因果过程可能跨"几天几年"）。多喂视频只会多给结果，不给机制的直接证据。
- 作者的例子（[[topics/papers/代码世界模型与神经渲染/1-01_2608.25927_CodeWorldModel.pdf#page=2|第 2 页]]、§3.1）：玩家刺杀了城主后离开，继承、治安、贸易、派系、NPC 的信念和行为都应该在玩家不在时继续演化，玩家很久后回来才看到结果。这需要常识推理、长程规划、持续预测后果，纯视频模型目前做不到。
- 两种要求截然不同：**稀疏但语义复杂的推理**（适合语言模型）和**稠密重复的执行**（位置、冷却、碰撞、伤害，适合代码）。每一步都调语言模型既贵又不可复现，所以要把决策"编译"成代码。
- 剩下的问题：**状态怎么交给视频模型**。纯文字条件给不了精确的逐帧位置和相机轨迹；让智能体搭完整 3D 世界再渲染又太贵、而且提前锁死了最终外观。

## 方法

总览见 [[topics/papers/代码世界模型与神经渲染/1-01_2608.25927_CodeWorldModel.pdf#page=3|图 2（第 3 页）]]：交互意图 → 编码智能体写 / 调代码 → 代码更新世界状态 → 状态编译成代理 + 文字 → 视频模型生成画面 → 画面和状态反馈回去。

### 世界状态的形式化（§3.1，第 7 页）

- 把完整状态拆成两部分：$S_t = (S^{exe}_t, S^{vis}_t)$
  - **可执行状态** $S^{exe}_t$：不断演化的世界程序本身、实体属性、规则、关系、事件历史等可直接操作的变量。
  - **视觉状态** $S^{vis}_t$：视频模型生成的、需要随时间保持一致的外观和运动信息。
- 更新：$S^{exe}_{t+1} = T_{AC}(S^{exe}_t, A_t)$（智能体 + 代码的联合转移），$S^{vis}_{t+1} \sim G_\theta(S^{vis}_t, S^{exe}_{t+1})$。
- 作者特意说明：把 $S^{exe}$ 写成 $G_\theta$ 的输入只是抽象依赖，不是把原始代码喂给网络；需要持久的视觉信息"保存在世界状态里、由智能体管理，相关角色 / 地点再出现时重新提供"。实际实现里这件事只靠一张首帧外观锚图完成（见下文"推理"）。

### 智能体–代码的两种频率

| 角色 | 频率 | 做什么 |
|---|---|---|
| 编码智能体 | 低频、事件驱动 | 解释新事件、联系世界知识和人物关系、决定哪些实体和机制受影响、规划长期后果；调用已有代码或**局部改写世界程序**（不只改当前状态，也改世界以后怎么运作） |
| 代码 | 高频、确定性 | 按现有规则更新位置、朝向、数值属性、碰撞、攻击范围、冷却、命中、伤害、连锁触发；执行频率和智能体推理频率、视频生成帧率都解耦 |
| 视频模型 | 按生成调用 | 根据代理 + 文字生成外观、运动、细粒度交互 |

执行结果、测试、新的世界反馈回到智能体，作为下一次决策的证据。作者强调代码"既不是冻结的游戏逻辑，也不是独立于智能体的控制器，而是智能体持续维护的可执行延伸"。

### 状态 → 视频模型的条件：proxy（§3.2）

- **先试过纯文字**：作者用大规模训练的视频世界模型（参考文献 [31]，LingBot-World 2.0 / "Infinite worlds with versatile interactions"）测试，即使配了专门的相机条件通路，文字仍控制不准相机轨迹和实体运动。论断是"语言理论上能描述每个像素，但 token 效率太低、视频模型也跟不住"。**这个实验没有给数字或图**。
- **proxy 的定义**：把影响当前观测的相机、实体位置、姿态、轨迹、空间关系组织成一个粗糙的可编程世界表示，再由**确定性编译器**做轻量光栅化得到代理视频。设计原则：
  - 条件里的每个控制信号都必须**可追溯到世界状态**，不接入别的生成模型（比如学习式 3D 生成器），保证状态到条件这一段对智能体是白盒；
  - 只保留观测必须服从的粗结构和交互状态，不表达纹理、材质、细光照；
  - 智能体用一组**几行代码就能写出的简单原语**组合而成，参数可寻址（位置、尺度、姿态、布局、相机、状态标记），可局部编辑。
- **双通道**：文字传语义意图（身份外观、动作语义、代理没写的动态细节），代理视频传逐帧时空约束。
- **条件带宽**（第 8–9 页）：代理越丰富，接地越强，但智能体要构造和维护的原语和参数越多。例如如果代理编码关节级运动，推理时智能体就得写关节轨迹，而目前的编码智能体做不可靠。所以原则是"当前观测必须服从的最小充分状态"，外观和细粒度动态留给视频模型。
- **token 开销**：代理每个空间维度取目标的 1/4，所以只给 omni transformer 增加目标视频 1/16 的视觉 token，作者称推理负担可忽略。
- **定位**：proxy 被看作文字提示的"视觉对应物"，完整系统里应由智能体自己决定开 / 关 / 调整代理（选关键实体、调分辨率和帧率）；但**本文只实现并评估了一种固定的代理设计**。

### 配对数据（§3.3，[[topics/papers/代码世界模型与神经渲染/1-01_2608.25927_CodeWorldModel.pdf#page=9|图 3，第 9 页]]）

| 来源 | 目标视频 | 代理怎么来 | 是否用于训练 |
|---|---|---|---|
| 游戏录像 | 游玩时同步录下的画面 | 从同一次运行里只记录构造代理需要的状态：相机、实体位置和朝向、近似尺度、场景布局、交互关键状态；**不留**完整 3D 模型、纹理、材质；按目标视频的相机轨迹程序化渲出代理；运行时还给出逐像素实例图，把文字里每个身份的描述绑定到对应区域 | 是（全部训练数据） |
| 真实视频（KITTI-360） | 校正后的 RGB 帧 | 离线用标定位姿、累积的语义 3D 重建、3D 物体标注编译：静态场景投影出度量深度和由深度导出的法线；行人用胶囊骨架、车辆用线框、植被用低模、大建筑用粗 3D 范围，共用一个深度缓冲光栅化 | **否**，只是证明能构造配对的概念验证 |

- 同一份运行记录可以重新编译成不同覆盖范围和粒度的代理，不用重新录目标视频。
- 原语词表不必固定；对简单原语区分不了的复杂物体，只用**包围盒**标位置和大致范围，身份和属性交给文字。作者称编码智能体能自主决定"用原语还是退回包围盒"。
- 好处：动作后果和相机运动都直接体现在代理视频里，**不需要动作标签和相机位姿标注**，所以真实视频更容易接入。
- 为了推理时智能体能复现，游戏代理**故意排除骨骼姿态、精细 3D 模型**等难以由智能体构造的表示。

### 训练配置（§4.1，[[topics/papers/代码世界模型与神经渲染/1-01_2608.25927_CodeWorldModel.pdf#page=11|第 11 页]]）

| 项目 | 设置 |
|---|---|
| 骨干 | 官方 MiniMax-H3 **Ref2VA** checkpoint（论文没写参数量） |
| 数据 | 157 段游戏录像，约 5.6 小时；以 2 秒间隔采出 9,420 个 5 秒片段 |
| 目标 | 124 帧、1344×768、24 FPS |
| 代理条件 | 124 帧、336×192，**固定对数深度 + 类别语义 ID 图** |
| 多模态编码器输入 | 系统指令 + 片段文字描述 + 11 张代理帧（偏移 0, 12, 24, …, 120） |
| 微调方式 | 全部 50 个 transformer block 上 rank-128 LoRA，约 5.96 亿可训练参数；只优化视频目标，关掉音频损失 |
| 优化 | AdamW，全局 batch 8，weight decay 0.01，梯度裁剪 1.0，BF16，FlashAttention-3，梯度检查点 |
| 学习率 | 100 步 warmup 后余弦从 2e-5 降到 1e-6 |
| 规模 | 3 个 epoch，共 3,534 步，8 张 H800（9420/8≈1178 步/epoch，×3 对得上） |

### 推理（§4.1 后半，第 11–12 页）

- **编码智能体**：GPT-5.6 Sol。给它现成的游戏引擎代码（基本玩家操控、碰撞、运行时更新循环）和训练时同一套代理原语。作者承认从零写 AAA 级场景和复杂交互还很难，但智能体可以**拿现成的 AAA 游戏场景和玩法逻辑当模板**组合、扩展、改写。得到的世界可执行、可由玩家操控，只是用粗几何表示视觉相关状态。
- **首帧外观锚**：GPT Image 2 根据第一张代理帧和智能体写的文字生成 1536×864 的首帧（要求保持代理规定的实体数、位置、尺度、朝向、布局、相机高度），缩放到 1344×768 后同时用作目标潜变量第 0 帧、多模态编码器输入和 Ref2VA 外观参考。
- **采样**：用第 3,534 步的 checkpoint，显式 Euler 20 步；每次调用生成 124 帧 1344×768、24 FPS。只生成视频，H800 上跑。
- **长视频**：124 帧窗口、34 帧重叠，每个新窗口前进 90 帧；后一个窗口用前一个窗口最后 34 帧 RGB 当续写上下文，并**每个窗口重复提供同一张外观锚图**；拼接时丢掉重生成的 34 帧重叠部分。外观一致性靠"重叠帧保局部连续 + 同一锚图保全局身份"。
- **不是流式 / 实时**：这是离线的滑窗续写，论文在局限里明确说没有实现自回归实时生成；评测"为了隔离控制质量，不考虑推理延迟"。

## 局限 / 存疑

作者自己承认的（§5，[[topics/papers/代码世界模型与神经渲染/1-01_2608.25927_CodeWorldModel.pdf#page=12|第 12 页]]）：

- 受算力限制，训练规模小，生成质量仍有限；**没有实现自回归实时生成**。
- 编码智能体还写不好高度复杂的游戏机制，原型**没有展示自主构建完整开放世界游戏或仿真器**。

读的时候值得核对的：

- **没有定量评测**：代理跟随精度（例如从生成画面重估深度 / 分割与代理比较）、画质、与文字条件或动作条件基线的对比全都没有数字，"更精确、更灵敏的控制"只靠项目页视频。§3.2 用来否定纯文字条件的那个实验也只有一句结论。
- **"世界大脑"部分基本没被实验检验**：引言和 §3.1 花大量篇幅讲刺杀城主、画面外后果、智能体改写机制，但实验里智能体只做了"拿现成游戏模板搭简单可操控世界、写提示词"，录下的代理视频由用户操控产生。持久后果、画面外演化、机制改写都没有演示。
- **"视觉状态"的持久化只是一张锚图**：形式化里说需要持久的视觉信息由智能体管理并在重新出现时提供，实际实现只是每个窗口重复喂同一张 GPT Image 2 首帧 + 34 帧重叠。新出现的角色、离开再回来的地点怎么保持外观没有机制（需核对项目页 / 代码）。
- **外观有多少来自 GPT Image 2**：图 4 的风格化效果（卡通、水墨、赛璐璐）首帧都是 GPT Image 2 生成的，H3 主要负责按代理延续。所以"5 小时 GTA V 就泛化到多种风格"里有多少是 H3 的功劳、多少是首帧图像模型的功劳，论文没有拆开（比如不给锚图的对照）。
- **代理视频怎么进网络没说全**：§4.1 说多模态编码器只收 11 张代理帧，但第 9、12 页又说逐帧代理以 1/16 token 进入 omni transformer、"完整代理序列提供逐帧控制"。两条路径分别怎么注入（拼 token？走参考通路？）需核对代码。
- **训练和推理的代理来源不同**：训练代理来自 GTA V 运行时记录，推理代理来自编码智能体搭的世界（同一套原语）。两者分布差多少、是否需要对齐没有讨论。GTA V 运行时状态怎么抓出来（mod？脚本钩子？）也没写，"GTA V"这个名字只出现在图 4 图注里。
- **小的前后不一**：
  - 数据时长：§4.1 写约 5.6 小时，图 4 图注写"5 小时"。
  - 骨骼：图 3 图注说游戏代理**排除骨骼姿态**以便智能体复现，但 KITTI-360 的代理给行人用的是"胶囊骨架"。是否只是形状不同、并非关节姿态，需核对图 3b。

## 摘要（中文）

世界模型旨在模拟复杂环境在动作和事件作用下如何演化，但现有基于视频的世界模型主要从视觉观测中学习动态，而视觉观测揭示的是结果，而非支配世界演化的知识、规则和机制。这使得维持持久后果、支持连贯的开放式演化变得困难。我们提出 Code World Model，一个把世界演化与视觉实现分离的框架，结合了语言模型的推理与编码能力和视频模型的生成先验。编码智能体充当世界大脑，推理事件及其后果，生成可执行代码来维护持久的世界状态并进行符合规则的演化。为了把可执行状态与视觉生成连接起来，我们引入一种代理表示（proxy），它编码逐帧的时空约束，并被编译成代理视频，条件视频模型渲染高保真的视觉观测。我们还开发了从游戏录像和真实视频构建对齐的代理–观测配对的数据管线。在配对游戏数据上微调后，MiniMax-H3 能遵循由编码智能体构建的简单交互世界给出的基于代理的时空规范，同时保留丰富的视觉细节和动态。这些结果展示了把代码用于持久的世界演化、把视频模型用于灵活的视觉实现相结合的潜力，为开放式世界模型提供了一条新路径。
