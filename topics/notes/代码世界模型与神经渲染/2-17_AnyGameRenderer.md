## 一句话总结

编码智能体几分钟就能写出能玩的小游戏，但画面是"程序员美术"——灰盒、彩色几何体、语义平涂色块。本文在 **MiniMax-H3 ref2va（33B）** 上训一个 **rank-128 LoRA**，把这种粗糙游戏录像当普通参考视频 `<Video 1>` 输入，配上一段按"对应契约"写的六段式 caption（"每个蓝色圆柱是一只戴面具的黑狼人""位置、大小、时机、数量完全保留""空的地方保持空"）和可选风格锚图，逐帧对齐地渲成目标风格。重点不是画质而是**实体对应**：数量对、出现消失的帧对、小目标不丢、不凭空加角色。训练数据 **10,330 段**（约 14.8 小时）来自三处：38 个智能体做的游戏（多路渲染）、Unreal Engine 里专门脚本化"同色群体增减、20–600 像素大小"的场景、用 3D 框检测重建的真实游戏录像。自建 59 例 / 753 个实体的实体级基准，相比零样本 H3：时间匹配 **50.9% → 62.9%**、位置匹配 57.1% → 61.9%、未渲染率 4.1% → 2.9%、幻觉率 52.1% → 46.0%、漏掉的数量变化 34.7% → 21.3%。20 步采样，README 说单卡 H100 一段 124 帧约 **17 分钟**，是离线渲染器。

## 要解决什么问题

"引擎管状态、生成模型只画像素"已经是共识（作者列了 CWM、PWM、Matrix-Game 4.0、StreamRender-H3、Marionette、SolarRenderer），作者不再论证这个设定，而是要做一个**接受的输入更宽、保留的东西更准**的渲染层（第 1 页 §1）。三个具体目标（第 2–3 页）：

1. **跨游戏类型泛化**：以往工作主要演示第三人称、第一人称或驾驶画面，而智能体真正做出来的是塔防、自走棋、俯视角幸存者、回合制、卡丁车、人群跑酷、竞技场、合作、射击这些类型。
2. **保持实体对应**：游戏渲染难在"记账"——12 个敌人死 3 个要变 9 个、援军在 4.2 秒走进来、远处小怪不能化进雾里。零样本模型常见三种错误：色块原样留在画面里没渲、该出现的实体不出现、输入里没有的角色被加进来。
3. **输入就是普通视频**：不要求 G-buffer、逐物体类别标签（作者把 StreamRender-H3、CWM 归为这类）、带状态的 3D 框（PWM）或低模代理（Matrix-Game 4.0）；灰盒、彩色几何体、语义色图、线框、粗黏土人都直接吃，一个检查点。

另外，现有渲染器只在帧级评测（边缘一致、点跟踪、两两评判），**看不出每个实体是否渲对**；边缘一致甚至会奖励"把色块原样留着"。

## 方法

总览见 [[topics/papers/代码世界模型与神经渲染/2-17_2610.31466_AnyGameRenderer.pdf#page=5|图 2，第 5 页]]。把游戏渲染当成**参考条件的视频编辑**。

| 项目 | 内容 |
|---|---|
| 世界状态由谁维护 | 不在本文范围：游戏代码和引擎（编码智能体写的小游戏、UE 场景）维护；渲染器只看录像 |
| 条件信号 | 粗糙游戏录像（作为参考视频 `<Video 1>`）+ 六段式 caption + 可选锚图（训练时是目标首帧，推理时当风格参考或省略） |
| 骨干 | MiniMax-H3 ref2va，33B，**冻结**；24 fps、最高 768p；训练关掉音频损失、推理丢弃音频（README 说输出带生成音频，见"局限"） |
| 可训练部分 | rank-128 LoRA，所有 Transformer 块（图 2 标在自注意力和 FFN 上） |
| 条件注入 | 走 H3 原生参考通路：文本、`<Video 1>`、锚图、带噪目标 token 拼成一条序列；不加 ControlNet、不加类型标识 |
| 推理 | 20 步 Euler；LoRA 系数域内 1.0，域外纯文字风格建议 0.7 |
| 输出 | 与输入同长同分辨率（训练固定 1344×768、124 帧） |

### 任务定义（§3.1）

给粗糙片段 V_in 和描述目标风格及"每个粗糙实体代表什么"的文字 c，输出 V_out，要求：(i) 相机、布局、时机逐帧一致；(ii) 每个粗糙实体变成对应的成品，位置、视觉大小、朝向不变，在同一帧出现和消失；(iii) 材质、光照、角色设计、环境跟随 c 和可选锚图 I_a。换风格只需换 prompt 或锚图。

### caption 的"对应契约"（§3.2）

沿用 H3 的六段格式（subject_definitions、summary、retention_analysis、detailed_description、overall_soundscape、non_diegetic_music），加四条规则：

| 规则 | 做法 |
|---|---|
| 主体是实体，粗糙形状只是它的表示 | 例："`<Video 1>` 里每个蓝色椭球是一只浣熊样的果园强盗，整个蓝色群体是一群相同的个体"。颜色到身份的映射每段单独定；群体按类描述，并明说它们存在 |
| retention_analysis 固定跟随输入的东西 | 声明位置、视觉大小、时机、人数完全保留，外观交给 prompt；空白区域用**正面句**描述："`<Video 1>` 里空的地方保持空，没有基本形状的地方不加角色" |
| 只用正面陈述 | H3 没有负向提示，而负面措辞往往生成它提到的东西（写"no HUD"会稳定生成 HUD） |
| 程序生成 caption，故意带噪声 | caption 由引擎元数据和检测结果自动生成；**列出游戏里所有可能出现的角色，即使这段里没出现**。目的是让模型学会"存不存在看视频，不看文字"，作者说因此很少再加入 caption 提到但输入里没有的角色 |

### 训练配方（§3.3）

- 统一格式：所有来源重采样成 124 帧、24 fps（5.17 s）、1344×768，目标首帧当锚图，配静音 32 kHz 音轨；潜变量和文本嵌入每个来源缓存一次。
- 优化：rank-128 LoRA，全局 batch 16；学习率 100 步预热后余弦衰减，峰值在 2×10⁻⁵ 到 2.8×10⁻⁵ 之间（没说哪个用于最终模型）；weight decay 0.01；bf16、梯度检查点、block swapping，FlashAttention-3 每步提速约 30%。
- 算力：**16 张 H200**；每步约 129 s；在 10,330 段上训 3 个 epoch 约 48 小时（这组数字对不上，见"局限 / 存疑"）。
- 部署：域内输入和风格用 LoRA 系数 1.0；域外纯文字风格（没有锚图、风格没见过）用 0.7，作者说能恢复零样本的画质、同时保留对应性提升，建议作为开放风格的默认值。

### 数据（§4、[[topics/papers/代码世界模型与神经渲染/2-17_2610.31466_AnyGameRenderer.pdf#page=7|表 1，第 7 页]]）

三个来源里粗糙视频和成品视频都是同一相机、同一布局、按构造逐帧对齐。

| 来源 | 粗糙输入 | 片段 | 占比 | 主要作用 |
|---|---|---|---|---|
| 38 个智能体做的游戏（多路渲染） | 每段 5 路对齐：目标渲染、primitive（灰盒 + 几何体角色）、coarse（更细的灰盒 + 低模黏土人）、12 类语义图、深度；另附锚图、caption、3D 框。**训练只用 primitive → 目标这一对** | 3,221 | 31% | 跨类型、跨输入形式泛化（射击、幸存者、塔防、卡丁车、竞技场、合作） |
| Unreal Engine（双路渲染） | 同一仿真和相机下渲两路：灰盒 + 彩色角色块，以及完整渲染；主角永远是蓝色，其他角色用 6 色 | 3,910 | 38% | 专门针对零样本的失败：同色群体 2–20 人中途走入 / 生成 / 走出 / 消失（密集、纵列、分散）；不同颜色角色进出；实体大小 20–600 像素（含 boss 和朝 / 背向相机移动）；视角 35% 跟随、30% 俯视、20% 等距、15% 侧视；只留主角在 ≥95% 帧可见的片段 |

| 合计 | | 10,330 | | 约 14.8 小时（10,330 × 5.17 s ≈ 14.83 h，算得上） |

- 真实录像和检测方法由 PWM 一作 Zheng-Hui Huang 提供，UE 渲染仓库由另外两位提供（致谢，第 10 页）。
- **智能体做的游戏的"目标渲染"从哪来没交代**：游戏是编码智能体写的，那带完整美术的目标画面用的是什么资产、谁做的，论文没说。用的是哪个编码智能体也没写。需核对。

## 实验与关键数字

### 基准与指标（§5.1）

- **59 例 / 753 个标注实体**：UE 双路渲染留出 11 例（灰盒）、真实录像 14 例（检测出的实心框）、6 个留出的智能体游戏的多路渲染 34 例。每例的源片段都没进训练，渲染风格或角色也是训练没见过的。所有模型同 seed、20 步、同一段 caption。
- **实体同步指标**（第 8 页）：输入实体用粗糙视频自带的真值 2D 框（存在不足 12 帧的忽略）；生成视频里用 **SAM3 开放词表分割**找角色（提示词 = caption 的主体短语 + 通用的人 / 车词），去掉阴影和倒影检测后连成轨迹；逐帧匈牙利匹配，IoU ≥ 0.3 或质心偏移在半个框尺寸内才算匹配。

| 指标 | 定义 |
|---|---|
| 时间匹配 ↑ | 实体在输入中存在的帧与其轨迹"在位"帧的 IoU；迟到、缺席、消失后还逗留、身份互换都会拉低 |
| 位置匹配 ↑ | 匹配帧上 1 − d/(0.5 s)，d 为质心偏移，s 为输入框尺寸 |
| 未渲染率 ↓ | 输入色块仍以平涂色块形式可见的实体帧比例 |
| 幻觉率 ↓ | 检测到的实体帧中属于"不对应任何输入实体"的轨迹的比例 |
| 准时出现 ↑ | 首次连续两帧匹配的帧与输入首帧之差 \|Δ_on\| ≤ 4 帧（约 0.17 s） |
| 从未出现 ↓ | 从没被识别的实体比例 |
| 漏掉的数量变化 ↓ | 输入里 6 帧内增加 ≥2 个实体算一次数量变化（目标数取 t+8 帧），若之后 60 帧内检测数连续 3 帧 ≥ 目标数 − 1 就算复现；基准里共 75 次 |

- **GT 下限（GT floor）**：把真值 RGB 视频走一遍同样的检测匹配流程，代表这套流程能测到的最好成绩。

|---|---|---|---|---|---|---|---|---|
| 全部（59） | 零样本 H3 | 50.9 | 57.1 | 4.1 | 52.1 | 55.9 | 26.0 | 34.7 |
| | **本文** | **62.9** | **61.9** | **2.9** | **46.0** | **67.6** | **20.2** | **21.3** |
| | GT 下限 | 80.9 | 79.3 | 0.1 | 34.1 | 93.6 | 0.7 | 0.0 |
| 多路渲染（34） | 零样本 H3 | 47.6 | 56.4 | 4.5 | 55.4 | 50.9 | 28.4 | 40.7 |
| | **本文** | **60.7** | **60.6** | **3.2** | **51.2** | **64.0** | **23.5** | **23.7** |
| | GT 下限 | 79.3 | 76.8 | 0.1 | 35.7 | 91.5 | 0.9 | 0.0 |

（粗体照原表。）

- **按来源差别很大**：智能体游戏上时间匹配 +13 点、漏数量变化几乎减半；UE 上时间匹配 96.6%，接近 GT 下限 98.5%，没有实体从未出现；**真实录像提升最小**：时间匹配 46.5 → 51.1，未渲染率反而 2.6 → 2.9，漏数量变化不变（20.0）。
- 注意 UE 子集的提升最大，而训练数据里 38% 是专门针对这些失败脚本化的 UE 场景，留出例也来自同一套 UE 场景生成方式，属于最接近分布内的一组。
- **幻觉率的下限很高**：真值视频自己走一遍流程就有 34.1% 的"幻觉"，说明这个指标里有大量检测噪声；本文 46.0% 对比零样本 52.1%，离下限还差 12 点。

### 按游戏类型（[[topics/papers/代码世界模型与神经渲染/2-17_2610.31466_AnyGameRenderer.pdf#page=10|图 5，第 10 页]]，只有雷达图，没给数字）

- 基准分 5 类：第一人称射击、俯视角、第三人称、人群、载具。
- 时间匹配每类都提升，人群和第三人称涨得最多；未渲染率除人群类外都下降（人群类两个模型都接近 0）；位置匹配在载具类提升最多。
- **幻觉率在人群类下降，但在俯视角和第三人称类略升**。俯视角最难，两个模型的时间匹配都低。

### 定性（[[topics/papers/代码世界模型与神经渲染/2-17_2610.31466_AnyGameRenderer.pdf#page=9|图 4，第 9 页]]）

7 个留出例子：零样本 H3 把色块原样留着（果园里的蓝方块、竞技场里的青色圆柱、草地上本该是驼鹿的蓝圆柱）；风格离典型游戏画面太远时丢掉输入视角（俯视灰盒变成正面动漫群像或第一人称体素场景）；输入只有两个块却按 caption 加角色。本文在这些例子里都修好了。作者也说零样本模型在稀疏场景 + 干净 caption 时表现不错。

## 局限 / 存疑

- **训练时长对不上（需核对）**：10,330 段 × 3 epoch ÷ 全局 batch 16 ≈ 1,937 步，按每步约 129 s 算约 69 小时，而论文写"约 48 小时"。48 小时对应约 1,340 步、约 2 个 epoch。是每步时间、epoch 数还是 batch 写错，论文没说。
- **只和零样本底座比**：作者在相关工作里点名了 SolarRenderer、StreamRender-H3、CWM、Matrix-Game 4.0、PWM，也说自己"更通用、更忠实"，但**没有和任何一个比**，基线只有零样本 H3。特别是 [[topics/notes/代码世界模型与神经渲染/2-09_SolarRenderer|SolarRenderer]]（同骨干、同参考通路、也号称结构表示无关）和 [[topics/notes/代码世界模型与神经渲染/2-14_LynnReal-Omni|LynnReal-Omni]]（同骨干、接受游戏录像）是最直接的对照。
- **没有任何画质指标**：只报实体对应，不报美学、成像质量、FVD 或 VLM 评判。作者自己承认 LoRA 系数 1.0 在域外风格上会损失画质（所以建议 0.7），但 0.7 下的对应性数字没给，基准用的是 1.0 还是 0.7 也没写（基准例子都是"训练没见过的风格或角色"，按部署建议应属域外）。需核对。
- **"语义图、线框都能用"缺少定量支撑**：智能体游戏的 5 路渲染里训练只用了 primitive 一路，语义图、coarse、深度都没进训练；线框只在真实录像的代理里出现。基准里也只有灰盒、实心框和多路渲染例（论文没说多路渲染例用的是哪一路，推测是 primitive）。所以"任意粗糙输入都行"目前只有图 1 和 README 的定性示例。需核对。
- **"不需要逐物体类别标签"的说法要打折扣**：输入约定是每类实体一种饱和色，caption 里逐色写清"这个颜色代表什么"，而且 caption 由引擎元数据自动生成。类别信息其实编码在像素颜色 + caption 里，只是不需要单独的标签通道。和 StreamRender-H3 的 13 类语义图比，主要区别是颜色到类别的映射每段可变、类别数不固定。
- **评测流程本身有偏差来源**：生成视频里的实体用 SAM3 按 caption 的主体短语去找，所以"画成了什么"会影响能不能被找到；GT 下限的时间匹配只有 80.9%、幻觉率 34.1%，说明指标里检测噪声不小。位置匹配只在匹配上的帧算，漏检的实体不拉低它。
- **真实录像子集几乎没提升**：时间匹配 +4.6、未渲染率变差、漏数量变化不变；而这是离"把真实感带进来"最近的一组。
- **离实时很远**：20 步 Euler、单段约 17 分钟（README），没有蒸馏、没有流式。对"编码智能体写游戏 + 渲染器实时出画面"的完整闭环来说，它只是离线的风格化 / 资产预览工具。
- **音频说法不一**：论文说训练关掉音频损失、推理丢弃音频；README 说输出是"带生成音频"的 1344×768 视频。需核对。
- **版本**：v1 到 v3 在 6 天内连发三版，PDF 首页日期写 2026-10-30，比 v3 提交日（10-28）还晚两天；各版改了什么不清楚，数字是否随版本变过需核对。
- **引用写法**：对 Matrix-Game 4.0、StreamRender-H3、SolarRenderer 都以"技术报告、2026 年 10 月"引用，没给 arXiv 号；对 SolarRenderer 写"六种结构视频"，而 [[topics/notes/代码世界模型与神经渲染/2-09_SolarRenderer|SolarRenderer 笔记]]记的是训练中见过 5 类表示（另有 8 个数据来源），说法不同。需核对。

## 与其他论文的关系

- **同骨干（MiniMax-H3 Ref2VA）的渲染器**：
  - [[topics/notes/代码世界模型与神经渲染/2-09_SolarRenderer|SolarRenderer]]：最像的一篇——冻结 H3、走原生参考通路、不加类型标识、靠固定句式告诉模型"这段视频是什么、该跟随什么"。区别：SolarRenderer 让结构潜帧直接用目标帧的 RoPE 位置，并蒸馏到 4 步、有块因果流式变体，用 VLM 两两评判 Elo；本文用 H3 原生的参考位置（没说改过）、20 步离线，评实体级对应。两者都声称对表示形式无关，正好缺一次直接对比。
  - [[topics/notes/代码世界模型与神经渲染/2-14_LynnReal-Omni|LynnReal-Omni]]：同骨干的通用多任务模型，也接受游戏录像当对齐控制，但给每个输入打模态标签、控制时间轴错开 Δ>0；本文没和它比。
  - [[topics/notes/代码世界模型与神经渲染/1-01_CodeWorldModel|CWM]]：H3 + 12 类代理视频（深度 + 语义 ID）；[[topics/notes/代码世界模型与神经渲染/1-12_StreamRender-H3|StreamRender-H3]]：13 类语义图、流式两步。本文把它们归为"需要逐物体类别标签"的一类。
  - [[topics/notes/代码世界模型与神经渲染/1-15_GameWM|GameWM]]：用 H3 Ref2VA 把 GTA V 画面重渲成低模版和风格版来造配对数据；本文的思路方向相反，是把低模渲回成品。
- **同组（Alaya Lab / Kaipeng Zhang）的谱系**：[Generative World Renderer](https://arxiv.org/abs/2604.02329)（G-buffer → 画面，AlayaRenderer）→ [[topics/notes/代码世界模型与神经渲染/2-06_AlayaRenderer-Flash|AlayaRenderer-Flash]]（实时化）→ [[topics/notes/代码世界模型与神经渲染/1-04_ProgrammableWorldModel|PWM]]（真实录像 → 3D 有向框 → ControlNet 渲染）→ 本文（任意粗糙视频 → H3 LoRA）。真实录像子集直接沿用 PWM 的 3D 框重建方法和数据。条件从"引擎精确导出的 G-buffer"一路放宽到"随便画的粗糙视频"。
- **低模代理路线**：[[topics/notes/代码世界模型与神经渲染/1-11_Matrix-Game-4.0|Matrix-Game 4.0]] 用 UE5 里 1712 小时的像素对齐低模代理训练实时因果渲染器；本文的 UE 数据只有 3,910 段，但按失败模式（群体增减、大小、进出时机）专门设计，数据少而针对性强。
- **"代码世界"完整系统**：[[mirros/notes/01_AgentGarten|AgentGarten]]、Matrix-Game 4.0、[[topics/notes/代码世界模型与神经渲染/1-14_CoCode-World|CoCode-World]] 这类系统需要的正是一个"不管输入长什么样都能接、而且数量和时机不出错"的渲染层；本文把它单独拿出来做，但还没进闭环。
- **评测角度**：[[topics/notes/代码世界模型与神经渲染/3-04_WorldDraft|WorldDraft]] 测"世界保持 vs 视觉实现"的此消彼长（帧级、VLM 评），本文的实体级同步指标是更细的一刀：逐实体看时间、位置、未渲染和幻觉。两套指标互补，可以拿来一起评同一批渲染器。
- **和本库机器人 / 导航方向的联系**：
  - 三类数据里"真实录像 → 3D 框代理 → 配对"的做法，和 [RoboRender](https://arxiv.org/abs/2610.09254)（2-16）的"仿真渲染 → 逼真视频"是同一类视觉仿真到真实的问题，只是方向不同：本文是"粗 → 真"的风格化，配对靠检测重建。
  - 实体级指标对机器人尤其关键：如果拿生成式渲染器造感知或策略的训练数据，**凭空多出的行人、晚出现的车辆、丢掉的小目标会直接变成错误标签**。本文的幻觉率在最好情况下仍有 46%（GT 下限 34%），提醒这类渲染器还不能当"标签保持"的数据增强器用。导航任务（[[topics/视觉语言导航VLN]]）里依赖"物体在不在、在哪"的指令跟随，同样受这个问题影响。
  - 许可方面，底座是 MiniMax H3，社区许可限制用输出改进其他 AI 模型、并排除美国 / 欧盟 / 英国 / 韩国，拿来造机器人训练数据前要先看清。

## 摘要（中文）

AI 编码智能体现在几分钟就能做出可玩的小游戏，但结果通常是"程序员美术"：灰色白盒、彩色几何体和平涂的语义色块。我们提出 AnyGameRenderer，一个视频到视频的生成式渲染器，把这类画面变成带角色、运动细节和特效的高质量画面，同时自始至终保持布局、相机以及每个实体的位置和时机不变。AnyGameRenderer 能泛化到智能体常做的多种游戏类型，例如塔防、自走棋、俯视角幸存者、回合制战斗、卡丁车和人群跑酷。它把普通视频当作游戏状态输入，不需要引擎 G-buffer、逐物体类别标签或低模代理这类复杂表示；灰色白盒、彩色几何体、语义图和线框都可以作为输入。它还保持实体对应：群体数量保持正确，实体在正确的帧出现和消失。我们通过对 MiniMax-H3 ref2va（一个 33B 的参考视频条件视频生成模型）做 LoRA 微调来实现 AnyGameRenderer。训练使用约 1 万段配对片段，来自三个来源：(i) 38 个智能体制作的游戏的多路渲染数据；(ii) Unreal Engine 的双路渲染数据，其中程序化控制了人群、数量变化和实体大小；(iii) 真实游戏录像，通过 3D 框检测重建配对。为了评估实体对应，我们提出一个实体级基准，包含 59 个留出案例、753 个实体，按真值框打分。与底座模型相比，AnyGameRenderer 更好地保持了实体对应：时间匹配从 50.9% 升到 62.9%，漏掉的数量变化从 34.7% 降到 21.3%，被凭空生成或留着没渲染的实体也更少。
