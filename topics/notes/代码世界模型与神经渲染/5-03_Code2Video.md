## 一句话总结

"code2video"这个名字的出处，但它**完全不用视频扩散模型**：三个大模型智能体把一个知识点（如"什么是支持向量机"）变成可执行的 **Manim** 代码，直接渲染成教学视频——**Planner** 先写面向特定受众的大纲、再写分镜（每节 3–5 行讲稿 + 对应动画），并从 Google 图片和 Iconfinder 拉参考图和图标；**Coder** 按节并行写代码，出错时用 **ScopeRefine** 从"出错行 ±1"→"讲稿行对应的代码块"→"整节重写"逐级修；**Critic**（Gemini-2.5 Pro）看渲染出的视频，借一个把画布右侧切成 **6×6 锚点网格**的视觉提示和占用表，把重叠、遮挡、空白改成"挪到 B2 / 缩放 0.8"这类可直接执行的修改。同时提出 **MMMC** 基准（取自 3Blue1Brown 的 117 个长视频 + 339 个分段，13 个学科）和 **TeachQuiz** 指标：先用提示词让 VLM"忘掉"目标概念，再看它看完视频能答对多少题。用 Claude Opus 4.1 时，美学均分 87.9（直接写代码 37.8）、TeachQuiz 86.0（直接写代码 40.0）；Veo3 等像素模型 TeachQuiz 只有 0–2.5；人工评测里 TeachQuiz 80.3，略高于 3B1B 原片的 78.8。代价是每个主题约 14 分钟、4.3 万 token。

## 要解决什么问题

- **像素空间视频模型做不了教学视频**（§1、§2.1）：教学视频需要学科知识、精确的视觉结构（文字、公式、图形）和连贯的讲解顺序，还常常很长；文生视频模型在长程推理、多实体、板书式构图、清晰文字上都不行。
- **作者的直觉**：这类需求更适合"操控一个可渲染的环境"——用代码显式控制。代码路线的三个好处是**可扩展**（新的可视化和外部素材可以模块化接入）、**可解释**（每个顺序、布局、渲染决定都写在脚本里，可审计）、**可控**（时间顺序和空间排布都能精确指定）。
- **两个具体难点**：
  1. 怎么做出**时间上连贯**（概念按逻辑顺序引入、展开、巩固）且**空间上清晰**（元素不互相遮挡）的教学视频；
  2. 怎么评测教学视频——不能只看外观，要看**学了以后能不能会**。
- 编码智能体之前多用于静态图（图表、海报、示意图）或局部视觉任务；把代码生成和**动态的**教学视频结合是这篇的切入点。

## 方法

总览见 [[topics/papers/代码世界模型与神经渲染/5-03_2510.01174_Code2Video.pdf#page=5|图 4，第 5 页]]。任务形式化（§3.1）：把一个学习主题映射成可执行的 Manim 代码，渲染结果就是教学视频。选 Manim（Community v0.19.0）是因为它有细粒度时空控制、符号表达能力强，而且 3B1B 已经证明它能做专业教学视频。

### 和专题主线的对照：这里的"世界"和"渲染器"是什么

| 问题 | Code2Video 的答案 |
|---|---|
| 状态怎么用代码表示 | 没有可交互的世界状态。"状态"是一段**分镜**：每节的标题、讲稿行、与讲稿一一对应的动画步骤（JSON），再落成 Manim 的 `Scene` 类 |
| 谁写代码 | 通用大模型（实验里换了 Gemini-2.5 Pro、GPT-4o、o4-mini、GPT-4.1、GPT-5、Claude Opus 4.1），**不训练**，全靠提示词 |
| 渲染器 | Manim 本身，确定性渲染，**没有神经渲染器**；成片就是代码的直接输出 |
| 条件信号 | 不存在"引擎导出给视频模型的条件"；Critic 反过来用渲染出的视频给代码提修改意见 |
| 实时 / 流式 | 不涉及，离线生成，每个主题 8.8–16.8 分钟 |
| 外观一致 | 固定版式基类（黑底、左侧讲稿、右侧动画区、标题置顶）+ 跨节共享的素材缓存 |

### Planner：主题 → 分镜（§4.1）

| 步骤 | 输入 → 输出 | 要点 |
|---|---|---|
| 大纲 | 主题 Q（+ 一张参考图）→ 大纲 O = {o₁…oₙ} | 每节有 ID、标题、内容摘要、示例；**显式指定受众**（如三角函数对初中生、傅里叶定律对本科生），目标时长由参数给定 |
| 分镜 | 每个 oᵢ → 分镜 sᵢ | 关键节最多 5 行讲稿 + 5 个动画，其他节 3 + 3；讲稿行只允许在对应动画出现时变色；黑底、浅色、给出十六进制色值；尽量不画坐标轴 |
| 外部数据库 D | 分镜 → 素材关键词 → 检索 | (a) 与主题对齐的参考图（Google 图片，用 CLIP 相似度阈值过滤），用来减少幻觉、给大纲和分镜做视觉参考；(b) 难以从零画的图标（Iconfinder，如动物、人物、设备）。素材放进持久缓存，跨节复用 |

### Coder：分镜 → 可执行代码（§4.2）

- **按节并行**：每节 cᵢ = P_coder(sᵢ, A) 独立生成、独立调试，共享素材 A 保证各节视觉一致。作者说串行做完"生成 + 调试 + 渲染"一个视频可能超过两小时。
- **ScopeRefine（SR）逐级修错**：
  1. 行级：出错行 ±1 行，最多 K₁ 次局部修复；
  2. 块级：扩到该讲稿行对应的代码块 B_{i,j}，最多 K₂ 次；
  3. 全局：最后才按分镜整节重写。
  K₁、K₂ 的具体取值正文没给。代码里用 `# === Animation for Lecture Line k ===` 注释把代码块和讲稿行对上，块级修复靠的就是这个结构。

### Critic：用视觉锚点提示修版面（§4.3，[[topics/papers/代码世界模型与神经渲染/5-03_2510.01174_Code2Video.pdf#page=6|图 5，第 6 页]]）

- **问题**：大模型能看出"猫的图标放错了"，却说不出往哪个方向挪多远，纯文字的修改意见不能执行。
- **视觉锚点提示 P_vis**：把画布右侧（左侧是讲稿）离散成 **6×6 网格**（A1–F6），每格对应固定的 Manim 坐标，写成所有节都继承的基类方法 `place_at_grid(obj, 'B2', scale_factor=0.8)` 和 `place_in_area(obj, 'A1', 'C3', ...)`；小元素占一个点，大元素占一个矩形区域。把"连续定位"变成"选格子"。
- **占用表**：并行生成时记录每个元素占了哪些锚点、缩放多少、对应哪几行代码，于是 Critic 能把画面问题追回源代码，也知道哪些格子空着。
- **VideoLLM 反馈**：Critic 看渲染视频 + 本节代码，检查三类问题——同一格内元素重叠、动画挡住讲稿、大块空白导致失衡——输出 JSON 修改建议，再改代码重渲。
- Coder 的提示词明确禁止 `.to_edge()`、`.move_to()` 等手动定位，只许用网格方法。

### MMMC 基准与评测（§3.2–3.3、附录 A.1，[[topics/papers/代码世界模型与神经渲染/5-03_2510.01174_Code2Video.pdf#page=4|第 4–5 页]]）

| 项目 | 内容 |
|---|---|
| 来源 | 3Blue1Brown 全部 YouTube 视频，去掉问答等非教学内容 |
| 规模 | 117 个长视频（平均 1014 秒，约 16.9 分钟）+ 按作者时间戳切出的 339 个分段（平均 201 秒），共 456 个单元；LLM 从标题、描述、元数据里提取学习主题（平均 6.3 词） |
| 学科 | 13 类：分析、微积分、计算机、微分方程、流行病、几何、群论、线性代数、神经网络、物理、概率、谜题、拓扑 |
| 美学（AES） | Gemini-2.5 Pro 当裁判，5 个维度：元素布局 EL、吸引力 AT、逻辑流 LF、视觉一致 VC、准确与深度 AD；正文说"每维 100 分制"，附录提示词里是每维 0–20 分、总分 100 |
| TeachQuiz | 每个主题 10 道四选一题，偏"视觉化推理"（如"复平面上的点乘以 i 对应什么视觉变化？"）。① **遗忘**：用提示词让 Gemini-2.5 Pro 把该概念的定义、别名、公式、标准例子都当作禁用，依赖禁用知识时必须答"证据不足"；② **从视频重学**：只许用视频里出现的证据答题。TQ = 重学准确率 − 遗忘准确率 |
| 效率 | 每个主题的平均生成时间和 token 数 |

在 TheoremExplainAgent（TEA）的基准上按它的协议评（0–1 分）：Code2Video 总分比 TEA 高 0.06–0.10（GPT-4o 0.78 → 0.88，o3-mini 0.77 → 0.87，Gemini 2.0 Flash 0.76 → 0.82）；元素布局提升最大（GPT-4o 0.59 → 0.91）；Gemini 2.0 Flash 的视觉一致从 0.87 降到 0.70。表里"人做的 Manim 视频"总分只有 0.77，低于 Code2Video 的三个版本。

## 局限 / 存疑

- **"40%""50%""46%"其实是分数差，不是百分比**：摘要和引言说"比直接生成代码提升 40%""Claude Opus 4.1 美学提升 50%、TeachQuiz 提升 46%"，表 1 里对应的是 +39.5～+50.1 的**绝对分差**（相对提升其实超过一倍）；"直接写代码让 TeachQuiz 提升 30%"对应 Veo3 2.5 → 36.5～40.0，也是分差。读数时别当成相对比例。
- **"稳定 40% 提升"只在 3 个骨干上有对照**：Code LLM 基线只跑了 GPT-5、GPT-4.1、Claude Opus 4.1；Gemini-2.5 Pro、GPT-4o、o4-mini 没有直接写代码的基线。GPT-4o 版 TeachQuiz 只有 44.0、o4-mini 48.5，比 GPT-5 / GPT-4.1 直接写代码（36.5 / 37.0）高得不多，"稳定"要打折扣。
- **同一个模型身兼数职**：Gemini-2.5 Pro 既是所有配置的 Critic，又是美学裁判，又是 TeachQuiz 的"学生"。Code2Video · Gemini 版美学 57.4（各骨干最低）、TeachQuiz 却有 72.0，可能有自评偏置；没有换裁判的对照。
- **评测了多少个主题没说（需核对）**：MMMC 有 456 个单元（README 说"117 个主题"），但表 1 是在全部、长视频还是子集上算的，正文没有交代；人工评测是 20 个主题。TeachQuiz 的 10 道题是谁出的、有没有人工审核，也没说。
- **"遗忘"靠提示词**：Gemini-2.5 Pro 闭源，只能用提示词要求它"别用先验知识"；遗忘后准确率在三个骨干下都恰好是 5.0，说明这一步是同一套题、同一个学生的固定基线。模型是否真的不用先验、视频里的文字是否直接泄露了答案（只给讲稿文字就有 22–27 分），都很难从提示词层面保证。3B1B 原片 TeachQuiz 97.1、美学 99.7（三个维度满分）也可能部分来自裁判对 3B1B 的熟悉。
- **人工评测的两张表对不上（需核对）**：按 6 名初中生 + 2 名本科生加权，表 6 能还原表 4 里 3B1B 和 Veo3 的 TeachQuiz、CW，但 Code2Video（Claude）的 CW 算出来约 71.6，表 4 写的是 64.0；TeachQuiz 算出来约 79.8，表 4 是 80.3。另外人没有"遗忘"步骤，人工评测里的 TeachQuiz 具体怎么算（是否扣掉看视频前的成绩）没说。
- **人工评测样本小且时长悬殊**：每种视频只有 8 个人看；3B1B 原片 16.9 分钟、Code2Video 2 分钟、Veo3 只有 8 秒，比较的不是同等条件。"Code2Video 超过专业人工视频"只在人工 TeachQuiz（80.3 对 78.8）和初中生组成立，VLM TeachQuiz（86.0 对 97.1）和本科生组（55.0 对 56.0）都是原片更好；摘要的说法是"与人工制作的教程相当"。
- **像素模型的对比不对等**：Veo3、Wan2.2 只生成不到 8 秒的视频，被拿去和几分钟的教学视频比美学和 TeachQuiz，得 0 分基本是预料之中；表 1 里像素模型的"时间"（OpenSora 27.6 分钟）和代码路线的"时间"含义也不同。
- **小的不一致**：Critic 的提示词要求参考一张"reference image"做空间分析，正文没说这张图是什么；基类代码注释写"4x4 grid"实际定义的是 6×6；表 2、3 的骨干标成 "Chat-4.1"，应即 GPT-4.1；ScopeRefine 的 K₁、K₂ 没给数值。
- **范围**：只做 Manim 风格的数理教学动画（2D、黑底、左讲稿右动画的固定版式），没有配音合成的说明，也不涉及照片级画面或物理世界。

## 与其他论文的关系

- **在专题里的位置**：专题第五节"另一支 code2video"的命名来源。和第一节的代码世界系统（[[topics/notes/代码世界模型与神经渲染/1-01_CodeWorldModel|CWM]]、[[mirros/notes/01_AgentGarten|AgentGarten]]、[[topics/notes/代码世界模型与神经渲染/1-12_StreamRender-H3|StreamRender-H3]]、[[topics/notes/代码世界模型与神经渲染/1-11_Matrix-Game-4.0|Matrix-Game 4.0]]、[[topics/notes/代码世界模型与神经渲染/1-15_GameWM|GameWM]]）相比，它**既没有可交互的世界状态，也没有神经渲染器**：代码执行的结果就是成片。所以那条路线上最难的问题——条件信号怎么设计、渲染器会不会改写结构、外观怎么持续绑定（[[topics/notes/代码世界模型与神经渲染/3-04_WorldDraft|WorldDraft]]、[[topics/notes/代码世界模型与神经渲染/3-06_PROWBench|PROWBench]] 测的就是这些）——在这里都不存在；剩下的问题只有"代码对不对、版面好不好、讲得清不清楚"。代价是画面只能是 Manim 能画的矢量动画。
- **同一节的后续**：
  - [[topics/notes/代码世界模型与神经渲染/5-05_VideoCoCo|VideoCoCo]]、[[topics/notes/代码世界模型与神经渲染/5-06_Video-Coder|Video-Coder]]（本批将有笔记）把代码渲染结果从"成片"降为"草稿"：编码智能体写 Blender 程序渲出确定性草稿，再交给视频模型精修成真实画面——等于把 Code2Video 的"代码管结构"和第一节的"视频模型管外观"接起来。Video-Coder 还开始**训练**编码智能体（SFT + RL），而 Code2Video 完全靠提示通用大模型。
  - [GPT4Motion](https://arxiv.org/abs/2311.12631)、[Scene Co-pilot](https://arxiv.org/abs/2411.18644) 更早，用 Blender 物理脚本或程序化场景引导扩散模型；[PhysOPSD](https://arxiv.org/abs/2611.12411) 只在训练时把代码当特权信息。
- **评测上的后续**：[Code2Video-Compass](https://arxiv.org/abs/2610.28416)（3-09）把"写代码直接渲染成视频"推广到 2,104 个通用任务（文生、图生、视频生视频）；HeyGen 的 Code2Video Benchmark 评动效设计；[Animation2Code](https://arxiv.org/abs/2606.28593) 是逆方向（从动画视频重建代码）。TeachQuiz 的"先遗忘再看视频重学"是这一支里比较独特的评测思路，衡量的是信息传达而不是画质。
- **同类教学 / 解释视频智能体**：[TheoremExplainAgent](https://arxiv.org/abs/2502.19400)（附录直接在它的基准上比）、[Manimator](https://arxiv.org/abs/2507.14306)（论文转讲解视频）；共同一作 Kevin Qinghong Lin 参与的 [Paper2Poster](https://arxiv.org/abs/2505.21497) 是同一套"多智能体 + 视觉反馈修版面"思路用在静态海报上。
- **视觉锚点 = 把连续定位离散化给 VLM**：Critic 的 6×6 网格和"挪到 B2"本质上是让 VLM 从有限候选里选位置，而不是回归连续坐标；这和机器人 / 导航里让 VLM 在图像上选标记点或网格格子做空间决策的做法是同一个思路（VLM 擅长"选哪个"，不擅长"挪多少"）。[[topics/notes/代码世界模型与神经渲染/3-04_WorldDraft|WorldDraft]] 的 Primer 用 SVG 角标给视频模型做视觉提示，也是"用程序画的视觉标记弥补文字没有空间定位"的同类做法。
- **和自我改进的关系**：Critic 是测试时的"渲染 → 看 → 改代码"闭环，ScopeRefine 是测试时的逐级修错，都不更新模型参数，属于单次生成内的自我修正，而不是 [[topics/递归自我改进RSI]] 意义上的持续自我改进；后来的 Video-Coder 用 RL 训练编码智能体，才开始往"让写代码的智能体本身变强"走。
- **和机器人方向的距离**：这篇和机器人、导航基本没有直接联系；能借鉴的是工程层面的两点——按模块并行生成 + 局部修错（仿真场景代码生成同样受"一处报错整段作废"困扰，[[topics/notes/代码世界模型与神经渲染/1-01_CodeWorldModel|CWM]] 这类编码智能体搭世界也一样），以及"看渲染结果回改代码"的视觉反馈闭环。

## 摘要（中文）

近来的生成模型推动了像素空间的视频合成，但它们仍难以制作专业的教学视频，因为这类视频需要学科知识、精确的视觉结构和连贯的过渡，这限制了它们在教育场景中的应用。直观地说，这些要求更适合通过操控一个可渲染的环境来满足，而这种环境可以用逻辑指令（例如代码）显式控制。本文提出 Code2Video，一个以代码为中心、通过可执行 Python 代码生成教学视频的智能体框架。框架由三个协作的智能体组成：(i) Planner，把讲课内容组织成时间上连贯的流程并准备相应的视觉素材；(ii) Coder，把结构化指令转成可执行的 Python 代码，并结合范围引导的自动修复来提高效率；(iii) Critic，借助视觉语言模型（VLM）和视觉锚点提示来改进空间布局、保证清晰。为了系统评测，我们构建了 MMMC，一个由专业制作、分学科的教学视频组成的基准。我们在多个维度上评测 MMMC，包括 VLM 当裁判的美学分、代码效率，以及特别提出的 TeachQuiz——一个端到端指标，衡量 VLM 在"遗忘"之后看生成视频能恢复多少知识。结果显示 Code2Video 作为一种可扩展、可解释、可控的方法颇具潜力，比直接生成代码提升 40%，生成的视频可与人工制作的教程相当。代码和数据集已公开。
