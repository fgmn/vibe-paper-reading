# 代码世界模型与生成式神经渲染

> [!info] 这份清单怎么来的
> 2026 年下半年冒出一批工作，做法一样：**世界状态、规则、物理写成代码，在游戏引擎 / 仿真器里跑；视频扩散模型只当"渲染器"**，把引擎导出的粗糙结构信号（深度、法线、语义图、低模代理、G-buffer、3D 框）实时渲成逼真画面。和 Genie、Matrix-Game 2.0 这类"状态藏在生成画面里"的纯视频世界模型相对。
> - 以 [[mirros/notes/01_AgentGarten|AgentGarten]]、StreamRender-H3、MiniMax-H3 为起点，顺着 Matrix-Game 4.0（表 3、§7）和 GameWM（表 1、相关工作）的引用往外收集，再用网页搜索补漏。检索时间 2026-11-18。
> - 这个方向也叫 **code2video**（代码到视频）。同日按这个名字补检了一轮：对照了两个社区维护的清单 [Awesome-Code-World-Model](https://github.com/MichaelCao0/Awesome-Code-World-Model)（170 条）和 [Awesome-Code-World-Models](https://github.com/Danzer1xxxxChan/Awesome-Code-World-Models)（154 条，作者自称 2026-10-22 核对过一手来源），以及 Code2Video-Compass 的相关工作，补进 31 项：各节表格末尾"补充"部分，以及新增的第五节。
> - 没收的：只写代码、不接视频模型的"代码世界模型"（WorldCoder、ARC-AGI-3 上的各种程序化世界模型）、编码智能体搭 3D 场景（SceneCraft、VibeWorlding、Code2Worlds 等）、GUI 世界模型（Code2World、gWorld）、"视频 → 代码"的逆向重建基准（4DCodeBench、BVB、PhysCodeGym）。这些在上面两个清单里都有。
> - 有 arXiv 号的，标题、作者、首版日期都对照 arXiv API 核对过。有单篇笔记的 23 篇，表里的描述已按全文核对改过；其余各行"做法"是 Claude 根据摘要和别人的引用写的，读原文时请核对。

## 一句话脉络

1. **起点**：[[topics/notes/代码世界模型与神经渲染/1-01_CodeWorldModel|Code World Model]]（2026-08，西湖大学 + 南洋理工）提出"编码智能体当世界大脑 + 代理视频 + MiniMax-H3 渲染"的分工，之后大多数工作都引它。CWM 本身是离线的，没有定量结果。
2. **渲染器走向实时**：从 Streaming CWM（CWM 的流式改版）5.1 s/块（单卡 H200）→ AgentGarten 439 ms/块（H100）→ StreamRender-H3 扩散每步 218 ms（8×GB200）→ Matrix-Game 4.0 按键到画面 112 ms（单张 RTX 5090）。
3. **条件信号在变粗**：G-buffer（AlayaRenderer）→ 深度/法线（AgentGarten）→ 语义图（StreamRender-H3）→ 低模代理（Matrix-Game 4.0）→ 任意结构（SolarRenderer、EdenLive）。越粗，引擎越好写，渲染器补的东西越多。
4. **另一支 code2video**：不维护可交互的世界，只是为了生成一段视频先写程序。从 GPT4Motion（2023，Blender 物理脚本）到 Code2Video（Manim 教学视频，名字的出处），再到 VideoCoCo、Video-Coder（Blender 草稿 + 视频模型精修，后者开始专门训练编码智能体）和 PhysOPSD（代码只在训练时当特权信息），见第五节。
5. **下一步**：GameWM 认为渲染器不该只"换皮"，交互细节（火球怎么炸）也该由视频模型生成；WorldDraft 开始专门评测"代码建世界、视频模型只渲染"到底行不行，发现"保持世界"和"渲染属性"两者此消彼长。

### 实时性对比（摘自 Matrix-Game 4.0 表 3）

- 口径不统一：分块系统的数字是**两次块生成时间之和**，不含引擎和传输；Magpie 是作者自报的端到端（引擎 0.83 s + 传输 0.1 s + 渲染 0.62 s）；Matrix-Game 4.0 是游戏以 60 FPS 运行时的按键到画面。
- "开源"一栏是 Matrix-Game 4.0 作者在 2026-10-19 核对的，不是本库核对的。
- StreamRender-H3 的 258 ms/块是项目页各阶段中位数相加，项目页自己说明各阶段不能直接相加；同一次测量里实测每块出 RGB 是 272.73 ms（P50，用的是旧解码器），见 [[topics/notes/代码世界模型与神经渲染/1-12_StreamRender-H3|笔记]]。

## 五、Code2Video：编码智能体写程序来生成视频

和第一节的区别：这里不维护可交互的世界状态，而是为了**生成一段视频**先写程序（Blender、Manim 等），用程序的执行结果当草稿或成片。有的直接把代码渲染结果当成片（Code2Video），有的把它当成结构和运动条件交给视频模型（VideoCoCo、Video-Coder），有的只在训练时把代码当"特权信息"（PhysOPSD）。
